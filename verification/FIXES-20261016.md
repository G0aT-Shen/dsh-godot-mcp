# 配置恢复、退出清理与 MCP 取消修复

日期：2026-10-16。基于 `530c861` 的本地修改，对应技术评估中的配置丢失、会话清理与取消机制问题。

## 修改

- `src/inject.mjs`：重复注入时保留原始 override 备份，直到最终恢复；状态文件的 read/modify/write 在进程内串行执行，并通过临时文件 rename 原子替换，避免不同项目同时退出时丢失状态条目。
- `src/processes.mjs`：同一项目的启动、attach、detach 和清理串行处理；共享注入直到最后一个游戏或 attach 会话结束。自然退出登记可等待的清理 Promise，失败通过会话 `cleanupError` 报告。按 id 和 kind 停止共用注册表入口。
- `src/mcp-stdio.mjs`：接收消息不再等待长工具调用完成；工具操作保持串行，ping、发现和只读 status 可及时响应。每个请求有 AbortController；排队请求可取消，EOF/SIGINT/SIGTERM 会取消待处理请求。取消后抑制该请求的结果和进度响应；进度改为递增计数。
- `src/server.mjs`、`src/bridge.mjs`：取消信号传到 L1 进程执行和 L2/L3 网络连接；启动期间取消会回收刚创建的进程或 attach。TCP 连接关闭时立即拒绝等待者，同时修正超时等待者的移除逻辑。
- README 写明清理和取消的行为及边界。

## 回归证据

新增 `test/lifecycle.test.mjs`，已纳入 `npm test`。原实现上先运行的 8 项回归均失败；新增的两项桥取消回归也分别在修复前失败。修复后全部通过：

1. 连续三次注入再清理，原始 override 逐字节保留。
2. 子进程自然退出后无需显式 stop 即完成清理。
3. 按 kind 停止等待清理并还原用户配置。
4. 同项目并行游戏和 attach 的任一会话结束，不会提前移除共享注入。
5. 不同项目并行注入和恢复，不丢持久状态条目。
6. 长工具运行时 ping 及时响应；取消信号终止实际测试子进程，确认 PID 已退出。
7. 工具调用仍然串行，排队中的已取消写操作不执行；status 不被该队列阻塞。
8. 编辑器桥取消立即结束待响应连接。
9. 运行时桥取消立即结束待响应连接。
10. stdin EOF 取消未完成请求后关闭 controller。

`scripts/verify-l3.mjs` 另外新增四项真实 Godot 回归：自然退出后自动删除注入脚本、还原用户 override，以及按 kind 停止和再次启动后的同等检查。

## 范围与限制

- 桥取消关闭等待中的连接，不能撤销已经交给 Godot 的操作，也不承诺终止已经开始的 GDScript 协程。
- 同项目共享与状态写入串行保护限于单个 server 进程；多个独立 server 不应同时管理同一项目副本。
- 强杀 server 后的残留仍需通过 cleanup 回收。
- 评估中的自定义运行时端口问题、完整 MCP 版本协商不在本次三个修复项中，仍待处理。
- 本记录与修复源码一同提交。常驻 server 需要重启后才会加载新代码；本轮未重启用户正在使用的 DSH/server。
